# Docs review: PromptKit notes

The review procedure is the `docs-review` plugin's skill (from
[AltairaLabs/skills](https://github.com/AltairaLabs/skills)), configured by
`docs-kit.toml`, which points here for this repository's part of it. Where
this file and the skill disagree, this file wins. `docs/STYLE.md` is the
authority on what a page says.

## Getting the skill

`.claude/settings.json` declares the `altairalabs` marketplace and enables
`docs-review@altairalabs`. After trusting the folder, run
`/plugin install docs-review@altairalabs` if Claude Code has not offered it.
The skill runs as `/docs-review:docs-review <page-or-directory>`,
`/docs-review:docs-review --stale [path]` for upkeep.

The mechanical checks are the plugin's `docs-kit` tool, pinned in
`DOCS_KIT` in the `Makefile` and the docs workflows. `make docs-voice`,
`make docs-stale` and `make docs-coverage` run it through `uvx`, so you need
[uv](https://docs.astral.sh/uv/) installed. Bump the pin in the `Makefile`,
both workflows and `.claude/settings.json` together.

## Product and reader

PromptKit, the Go SDK and runtime libraries. Most "commands" in the docs are
Go snippets rather than CLI calls. Check them against the current API by
compiling them (a scratch `main.go` in a temporary module that `replace`s
`github.com/AltairaLabs/PromptKit/sdk` with `./sdk`), and against the
`sdk/examples/` modules, which have their own `go.mod`.

## Quadrants

`runtime/<quadrant>/` and `sdk/<quadrant>/`, where `<quadrant>` is
`tutorials`, `how-to`, `reference` or `explanation`. `concepts/` and
`architecture/` are explanation; top-level `reference/` and `glossary.md` are
reference. `contributors/` and `devops/` are for contributors, not the reader
in STYLE.md: review them for truth and voice, not quadrant.

## Verify sources (`{sources}`)

`runtime/` (providers, pipeline, tools, types, a2a, workflow engine), `sdk/`
(options in `sdk/options.go`, entry points in `sdk/sdk.go`), `pkg/config/`,
`server/a2a/` and `runtime/prompt/schema/promptpack.schema.json`. Claims about the
`promptarena` or `packc` CLIs are verified in
`github.com/AltairaLabs/promptarena`; mark them `unverified` if that
repository is not available.

## Generated and copied pages

- **Go doc comments are published.** `docs/scripts/gen-reference.sh` and
  `gen-sdk-reference.sh` turn them into committed pages under
  `runtime/reference/` and `sdk/reference/`. A generated page starts with
  `<!-- Code generated by gomarkdoc. DO NOT EDIT -->`; the other pages in
  those directories are authored. `make docs-api` also writes the gitignored
  `docs/src/content/docs/api/`. A doc comment is public documentation: an
  issue number in one ships to the reference page, and a URL written inline
  in one rendered as a live link and 404'd the docs build. Fix the comment,
  then regenerate with `make docs-reference` / `make docs-sdk-reference`;
  CI's Reference Drift check fails a hand-edit. A generated page gets no
  `verified` record, because regeneration overwrites its frontmatter.
- **Example READMEs are published.** `sdk/examples/<name>/README.md` is
  copied into `docs/src/content/docs/sdk/examples/` (gitignored) by
  `scripts/prepare-examples-docs.sh`. Review and edit the README.
- `docs/src/content/docs/reference/*-cli.txt` is generated; never edit it.
- `docs/local-backlog/` is gitignored and local-only. Never cite it, or a
  section number within it, from anything published.
- The docs workflow only runs for changes under `docs/`, so a doc-comment
  change elsewhere can break the site without any PR showing it.

## Checking commands

When checking flags, grep `sdk/examples/*/README.md` as well as the docs
tree: the published copies of those READMEs exist only after
`scripts/prepare-examples-docs.sh` runs.

The CLI is `promptarena`. Quickstarts once told readers to run `arena`, which
no binary provides, so the first command of two quickstarts could not be
followed. The PromptKit runtime and PromptArena both emit
`workflow state transition` with identical fields, so raw log counts are
twice the real number.

## Link check

`commands.check_links` binds port 4455 because a preview server already on
the default port makes the checker bind elsewhere and fail to start.
`npx astro preview stop` clears a stale preview daemon.

## Commits

Conventional (`docs:`), signed off: `git commit -s`. Run `make verify` first;
never `--no-verify`.
